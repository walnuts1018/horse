# オフライン評価

`mise run evaluation:run`は、保存済み抽出結果を正解データと照合し、JSON形式の指標を出力します。評価データセットを切り替える場合は`EVALUATION_DATASET`にファイルパスを設定します。Gemini APIは呼び出しません。

ケースには`sourceKind`を指定できます。出力の`sourceKinds`にはsource kindごとの文書数とモデル別Receipt精度、推定費用、平均レイテンシを出力します。出力の`models`には全source kindをまとめたモデル指標も出力します。ケースの`runs`には、実行ごとの`receipt`、費用metadata、`latencyMillis`を保存できます。Receiptのない失敗実行は精度の分母に含めず、費用とレイテンシには実行として集計します。`sourceKind`がないケースは`unknown`に集計します。

データセットにはバージョンと一意なケースIDを付け、原本画像を含めず、正解値と実行済みの抽出結果を保存します。実データを評価に使う場合は、利用者の同意とアクセス制御を確認し、公開リポジトリには追加しないでください。

品目はIoU 0.5以上の領域、印字金額、正規化した印字品名を使って一対一に対応付けます。金額評価では印字品名と領域だけ、商品名評価では金額と領域だけを対応付けに使い、評価対象の値が自身の正解候補を選ぶ根拠になることを避けます。各一致率は対応付け済み明細を分母にし、品目検出Recallで見落としを別に評価します。税額整合は`Verify`で評価し、領域一致precision、同じ印字名と金額の重複明細、人手修正操作数、自動確定可能率も集計します。正規化は空白・句読点・記号を除去した完全一致です。自動確定可能率は人手修正操作数が記録されたケースのうち、修正が0回だった割合です。

費用は`priceEstimateStatus`が`estimated_paid`または`free_tier`の実行だけを合算し、価格付き実行1件当たりの平均も出力します。金額は推定費用であり、請求実績ではありません。価格不明や為替レート未設定などの実行は`unpricedRuns`に計上します。

同梱データセットは人工的なレシート1件のみです。source kind別の出力形式を確認できますが、モデル間やsource kind間の精度・費用比較には不足しており、実際の日本語レシートに対する精度を示すものではありません。
