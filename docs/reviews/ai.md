# AIによる書類確認

## 会話による再確認

初回の抽出で確定しない情報は、ユーザーが原本の選択箇所や追加条件を会話で伝え、抽出結果を更新できる。書類詳細の会話欄から明示的に送信すると、Horseは同じ書類の新しい抽出ジョブを作成する。応答は日本語の説明と、レシートまたは明細の構造化データとして返る。

各ターンでHorseは選択済みモデル、現在の抽出、成功済みの会話履歴、原本をGemini Interactions APIへ送る。Gemini側の会話保存とバックグラウンド実行を無効にし、`previous_interaction_id`を使用しない。会話履歴は家庭に認可された抽出ジョブ結果へ保存する。GoogleのZDR方針ではInteractions APIの保存が既定で有効なため、`store=false`を明示する。

無料モデルの抽出は無料プロジェクトでのみ実行する。利用上限に達した書類を読み込むと、新規アップロード用のモデル選択を有料モデルへ変更する。ユーザーはモデルを再選択でき、有料APIはファイルのアップロードまたは再抽出・再確認を明示的に実行した場合だけ呼び出す。無料枠では入力がGoogleの製品改善に使われる場合があり、有料枠では使われないことをモデル選択欄と会話欄に表示する。利用上限に達した書類には有料モデルでの再抽出・再確認操作を表示する。両経路とも共有レート制御と入力トークン枠を通し、生成前にトークン数を確認して予約し、応答後にUsageまたは予約値で精算する。

再確認は抽出ジョブの新しい版として保存し、原本と過去版を保持する。会話による更新では既存の原本観察レコードを書き換えない。画面で編集中の手修正はローカル下書きとして残し、更新後の抽出結果と照合して再適用する。購入の確定や証拠の紐付けは既存のユーザー操作に残し、AIの応答から自動実行しない。

2026年10月15日に公式のモデル一覧と各モデル仕様を確認し、選択欄に設定している`gemini-3.8-flash`、`gemini-3.5-flash-lite`、`gemini-3.1-flash-lite`、`gemini-3.1-pro-preview`はいずれも画像/PDF入力に対応していることを確認した。先頭の3モデルは無料枠、`gemini-3.1-pro-preview`は有料枠でプレビュー版と表示する。`gemini-3.5-flash`は公式資料で非推奨となっており、`gemini-3.7-flash`は選択欄に追加していない。選択欄は公式の全モデルを自動掲載する一覧ではなく、Horseのrouteと費用記録を設定済みのモデルだけを表示する。

## 実装済みの範囲

- レシート、注文書類、カード明細、銀行明細に対する会話指示と構造化再抽出。
- 家庭メンバー認証、既存の抽出モデル選択、共有Geminiレート制御とトークン枠の使用。
- Geminiへの毎回の原本再送、`store=false`、構造化JSON応答、ローカル抽出履歴。
- 既存観察レコードを維持し、新しい抽出結果を通常の確認画面へ表示。
- 会話による更新をユーザーが送信した場合のみ実行し、有料モデルも画面上の明示操作を必要とする。
- モデル選択前に無料枠のデータ利用と、有料枠の料金・データ利用を表示する。
- 最新の再確認ジョブが失敗しても、画面には直近の成功結果と会話履歴を表示する。

## 残っている設計課題

- 応答のストリーミング表示はなく、既存の非同期抽出ジョブとポーリングで完了を待つ。
- 会話履歴は成功したターンだけ保存する。会話の分岐と過去版を指定した再開操作はまだない。
- レシート明細は版間で`key`またはregionが一致する場合だけ変更行として照合する。一致しない行は前回と今回の「照合なし」として分けて表示し、移動・追加・削除を確定しない。
