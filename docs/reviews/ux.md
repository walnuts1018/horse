# Horse フロントエンド UXレビュー

対象：[walnuts1018/horse](https://github.com/walnuts1018/horse) の `main`、commit [`e247076a`](https://github.com/walnuts1018/horse/commit/e247076a8bc26b0380641f549a7ad016baf07874)（2026年10月13日）。

今回はReactの書き方よりも、実際の操作でストレスが生じる箇所、誤ったデータを保存・表示する箇所、モバイルで使いづらい箇所を重視しました。

まだ実ブラウザでの操作テストは行っていないため、以下はソースコードを根拠にしたレビューです。見た目やタッチ操作の最終評価には実機検証が必要ですが、コードだけでも修正すべき問題がかなり見つかっています。

## P1：日常利用で大きな不満につながる問題

### 13. IndexedDB下書き保存の失敗から再試行できない

[下書きの自動保存](../../web/src/pages/purchase-create/ui/purchase-create-page.tsx)

編集後の状態表示は`savedAt`より`hasUnsavedChanges`を優先するようにし、古い保存時刻のまま「保存済み」と表示する問題を修正しました。IndexedDB保存失敗はエラー表示しますが、再試行操作がなく、次の編集まで保存を再実行しません。

### 14. 取り込み画面のカメラ導線を分けたい

[imports-page.tsx: file input](https://github.com/walnuts1018/horse/blob/e247076a8bc26b0380641f549a7ad016baf07874/web/src/pages/imports/ui/imports-page.tsx#L727-L752)

撮影用と複数ファイル選択用の入力を分け、画面にそれぞれの操作を用意しました。実機で撮影から送信までの導線は未確認です。

撮影した写真を送信前に確認し、回転・トリミングできる操作は未実装です。

## P2：情報設計と画面の分かりやすさ

### 15. 設定画面に日常的な業務が集まりすぎている

[settings-page.tsx](https://github.com/walnuts1018/horse/blob/e247076a8bc26b0380641f549a7ad016baf07874/web/src/pages/settings/ui/settings-page.tsx#L1087-L2398)

現在の設定画面には、マネープール、残高、決済元、カテゴリ、標準負担、優先ルール、商品マスタ、招待、タグ、予算、定期支出、資金移動、メンバーなどがまとめられています。

これらは性質がかなり異なります。

例えば、予算管理や口座間移動は「アプリの設定」ではなく、日常的な家計操作です。

すべてを設定の中に置くと、目的の機能を探しづらくなります。

おすすめは次の分類です。

| 場所      | 含める機能                       |
| ------- | --------------------------- |
| 帳簿      | 購入、返品、訂正、照合                 |
| 精算・資金移動 | 入金、貸付、返済、口座間移動              |
| 分析・予算   | 支出分析、月次予算、定期支出              |
| 設定      | 家庭、メンバー、口座、負担ルール、カテゴリ、商品マスタ |

これはすべてを別のトップレベルページに分けるという意味ではありません。設定内もタブやサブルートに分け、必要な情報だけを表示するのがよいです。

### 16. 帳簿検索のサーバー側絞り込みがない

帳簿の検索語、期間、カテゴリ、タグ、決済元などの条件はURLの検索パラメーターへ保存し、共有URLから再現できます。

検索処理は取得済みの購入履歴をブラウザで絞る方式です。データが増えると全ページ読み込みが発生するため、検索条件のうち主要なものをサーバー側へ移す必要があります。

### 17. エラー通知からの次の操作

通知の種類、アイコン、ライブリージョンは成功・エラー・警告・情報に分けました。エラーの種類に応じた再試行や入力修正などの操作は、各処理に必要なものを引き続き確認します。

### 18. 不確実な項目の確認順

原本と編集欄をデスクトップでは横並びにし、原本を固定しました。モバイルでは原本プレビューを折りたためます。不確実な品目や不一致金額だけを順に確認する操作は未実装です。

## P3：アクセシビリティと一貫性

### 19. キーボード・スクリーンリーダー向けの情報が不足している

CSSに`:focus-visible`があり、フォームにもARIAラベルがかなり追加されている点はよいです。

ただし、改善できるところがあります。

また、薄いグレーの補足文字と7〜9pxの文字は、コントラストや可読性の観点からも検証が必要です。

## 最後に：UXの回帰テストを導入すべき

現状、フロントエンドにはRelay生成物検証、TypeScript、Oxlint、Stylelint、Steigerなどが用意されています。しかし、リポジトリのフロントエンドにはPlaywrightなどによる実操作のE2Eテストが見当たりません。

UX改善を重ねるなら、Playwright + axe-coreによるブラウザテストを導入することを推奨します。

とくに以下の操作は必須の回帰テストにしたいです。

1. ネットワークが切れた状態で購入を保存し、復帰後に一度だけ登録される。
2. 同じ入金・送金を再試行しても二重記録されない。
3. ブラウザの戻る・進む・再読み込みで家庭と検索条件が維持される。
4. 320px、375px、430px程度のスマホ画面で、購入・取り込み・精算操作が横スクロールなしで完了できる。
5. キーボードのみで商品検索・品目追加・負担割合変更・確定まで操作できる。

テスト用のブラウザはChromiumだけでなく、WebKitとモバイルのビューポートを含めるとよいです。Android Chromeと実機Safariの操作検証は別途実施する価値があります。

## 総合評価

Horseは、機能の種類としては非常に充実してきています。購入履歴コピー、キーボードでの品目移動、オフラインOutbox、複数決済、AIの税計算候補、原本の位置表示、衝突時の再適用など、日常利用を考えた機能がすでに存在します。

ただ、現時点では多機能さに対して、操作の一貫性と分かりやすさが追いついていないと感じます。

特に改善効果が大きいのは、次の3つです。

第一に、入力・確認した内容が失われないことです。取込画面では編集内容を解析結果の更新から保護しましたが、他のフォームやタブ終了時の状態保持は引き続き確認が必要です。

第二に、数字が常に正しい範囲のデータを示すことです。ホームのグラフと分析途中の部分集計は、家計簿への信頼性に直結します。

第三に、スマホで日々の操作を少ないタップ・スクロールで完了できること。 現状の7〜10pxの文字と小さなボタン、品目入力までの長い導線は、かなり改善余地があります。

次に大きな機能を足すよりも、まずこれらを修正し、手入力なら数秒で登録、レシートなら不確実な箇所だけを確認して確定できる体験へ仕上げるのが、Horse全体の使い心地を高めるうえで最も効果的だと思います。
