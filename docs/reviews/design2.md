# Horse UI/UX 再レビュー

前回確認したコミット`6cef31f`から、現在の`main`（`fda8e33`）までの13コミットを比較しました。UI改善の中心は`522d148`（Enhance accessibility and styling across the application）です。

全体として、装飾を減らし、文字の可読性とタップ領域を改善した方向性はよいです。 特に、過剰な影やグラデーションの削減、フォームの44px対応、Skip Linkの追加は評価できます。

ただし、CSSの詳細を確認すると、修正が必要な退行が見つかりました。

## 1. 確実に修正すべき問題

P1・優先度高

### モバイルの「追加」ボタンのアイコンがほぼ見えなくなる

対象：[global.css L1866–1887](https://github.com/walnuts1018/horse/blob/fda8e338c8387c2893a6c805bdb1ba6b57bbc42e/web/src/app/styles/global.css#L1866-L1887)

今回追加されたCSSでは、モバイルナビゲーションのリンクに次の色が指定されています。

```
.mobile-dock.mobile-dock :is(button, a) {
  color: #596a61;
}
```

一方、中央の追加ボタンは以下です。

```
.mobile-dock.mobile-dock .dock-add {
  background: var(--green); /* #286d58 */
}
```

以前の`.mobile-dock .dock-add { color: #fff; }`より、今回のリンク共通ルールの方が詳細度が高いため、追加ボタンのアイコン色は`#596a61`になります。

背景色とのコントラスト比は約1.07:1で、ほぼ同化してしまいます。しかも今回、モバイルでは「追加」の文字が非表示になっています。

修正案

```
.mobile-dock.mobile-dock .dock-add {
  color: #fff;
}
```

これは最優先で修正すべきです。

### モバイルドロワーのキーボード・スクリーンリーダー対応が不十分

P1 — 既存から残っている問題

対象：[global.css L1410–1422](https://github.com/walnuts1018/horse/blob/fda8e338c8387c2893a6c805bdb1ba6b57bbc42e/web/src/app/styles/global.css#L1410-L1422)、[horse-app.tsx L433–440](https://github.com/walnuts1018/horse/blob/fda8e338c8387c2893a6c805bdb1ba6b57bbc42e/web/src/app/horse-app.tsx#L433-L440)

モバイルでは、サイドバーを閉じる際に次のCSSを使用しています。

```
.sidebar {
  transform: translateX(-100%);
}
```

しかし、`transform`で画面外に移動させても、内部のリンクやボタンはキーボードのTab移動対象に残ります。

そのため、閉じたサイドバーにフォーカスが入り、画面に見えないリンクへTab移動する可能性があります。

さらに、ドロワーを開いたときのフォーカス移動・閉じた後のフォーカス復帰・背景操作の制限も実装されていません。

修正すべきこと： モバイルのドロワーを適切なモーダルナビゲーションとして扱い、閉じた状態では内部要素をフォーカス対象とアクセシビリティツリーから外すことです。開いた状態ではフォーカス管理とEscapeによる終了を実装してください。

すでに利用しているBase UIを活用するのも有力です。

## 2. その他の修正推奨事項

### P2：ホーム画面のコンパクト化が一部反映されていない

対象：[home-page.css](https://github.com/walnuts1018/horse/blob/fda8e338c8387c2893a6c805bdb1ba6b57bbc42e/web/src/pages/home/ui/home-page.css)

今回、カードの無駄な高さを削減するために、以下が追加されています。

```
.spend-panel,
.settle-card {
  min-height: 0;
}
```

しかし、同じファイルの前半には次の指定が残っています。

```
.home-page .spend-panel,
.home-page .settle-card {
  min-height: 230px;
}
```

詳細度が高い後者が優先されるため、カードの最小高さ230pxは維持されたままです。

同様に、見出しの文字サイズや余白などにも、意図した上書きが効いていない箇所があります。

修正案： 後方に上書き用のCSSを追加していく方式をやめ、既存ルールそのものを修正・統合してください。不要な詳細度の引き上げも避けるべきです。

### P2：添付ファイルから親メールへ移動すると、レビューが消える可能性

対象：[import-document-review.tsx L51–80](https://github.com/walnuts1018/horse/blob/fda8e338c8387c2893a6c805bdb1ba6b57bbc42e/web/src/pages/imports/ui/import-document-review.tsx#L51-L80)

新たに追加された親メールへのリンクは、次の処理を実行します。

```
onClick={() =>
  onSelectDocument(document.attachmentParent!.id)
}
```

しかし、`imports-page.tsx`では、選択中の文書を現在ロードされている`documents`配列から検索しています。

```
const selectedDocument = documents.find(
  (document) => document.id === selected
);
```

文書一覧は50件単位のページネーションがあり、文書種別や期間などのフィルターにも対応しています。

したがって、親メールが現在の一覧に存在しない場合、親へのリンクを押すと`selectedDocument`が`undefined`になり、レビューが消えてしまいます。

修正案： 文書IDによる単独取得を実装するか、親子間移動に必要な文書をフィルター済み一覧と独立して保持してください。子文書への移動についても同じ問題があります。

### P2：初期設定が必要な家庭で、案内の優先順位が下がった

対象：[home-page.tsx L149–172](https://github.com/walnuts1018/horse/blob/fda8e338c8387c2893a6c805bdb1ba6b57bbc42e/web/src/pages/home/ui/home-page.tsx#L149-L172)

今回の変更で`SetupGuidance`が支出・精算サマリーより後ろに移動しました。

すでに利用している家庭では問題ありませんが、新規家庭では、まだ使える状態になっていない家計のサマリーが先に表示され、初期設定への導線が後回しになります。

初期設定が未完了の場合は、初期設定を優先表示し、完了後は通常のダッシュボードを主役にする方が自然です。

### P3：家庭切り替えボタンのARIA状態が実際の表示と一致しない

対象：[horse-app.tsx L462–492](https://github.com/walnuts1018/horse/blob/fda8e338c8387c2893a6c805bdb1ba6b57bbc42e/web/src/app/horse-app.tsx#L462-L492)

現在は家庭が1件でもボタンを押せますが、メニューは2件以上の場合しか表示されません。それでも`aria-expanded`は`true`になります。

家庭が1件のときはボタンの動作自体を再検討し、メニューの実際の開閉状態とARIA属性を一致させてください。

## 3. UI改善の完成度について

| 評価項目 | 今回の評価 |
| --------- | ---------- |
| 装飾の削減 | 改善している |
| 文字の可読性 | 改善している |
| タップ領域 | 改善している |
| デザインの一貫性 | 改善途中 |
| 操作フローの最適化 | 変更は限定的 |
| アクセシビリティ | 改善したが問題が残る |
| ブラウザ回帰テスト | 未整備 |

特に気になるのは、今回の変更がCSSによる視覚調整に偏っていることです。

例えば、帳簿の検索・編集フロー、買い物登録の連続入力、設定画面の操作構造などは、今回のUI改善コミットではほとんど変更されていません。

つまり、見た目の改善には取り組めていますが、以前依頼した「実際に使いやすくする」という部分には、まだ改善余地があります。

また、`web/package.json`とリポジトリ構成を見る限り、PlaywrightによるブラウザE2Eテストは追加されていません。今回のレビューもソースコード・差分に基づくもので、実際の画面を起動した視覚検証までは実施できていません。

## 4. 次に行うべきこと

次は再びアプリ全体をデザインし直すのではなく、以下の順序をおすすめします。

1. P1/P2の退行を修正する。 特にモバイルナビゲーションとCSS詳細度の問題。
2. 既存CSSを整理する。 末尾への上書き追加をやめ、各画面の実際のスタイル定義を統一する。
3. Playwrightで実画面を検証する。 モバイル、デスクトップ、キーボード操作、実データ相当の表示を確認する。
4. 日常操作のUX改善を進める。 買い物登録、帳簿、取り込み、精算の操作効率を中心に見直す。

総評：今回の改善は方向性として正しいですが、まだ完成とは言えません。 装飾過多だった部分を抑え、文字や操作領域を改善したのはよい変化です。

一方、実際の操作フローを改善した部分は少なく、CSSの詳細度による意図しない挙動も残っています。

今後はデザインSkillによる大規模な再生成よりも、既存UIを実ブラウザで操作し、具体的な不便さを一つずつ解消する工程に重点を移す方が、完成度を上げられると思います。
