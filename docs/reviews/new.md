# Horseの追加レビューで未解決の項目

## 2. SubscriptionごとのDBポーリング

購入Subscriptionと共有下書きSubscriptionは、接続ごとにDBを確認する構成からHousehold単位で購読をまとめる共有pollerへ変更した。購入イベントはHouseholdごとの最小cursorから1回のqueryで取得し、共有下書きもdraftごとの最小revisionから1回のqueryで取得する。同じHouseholdやdraftを購読する接続には、取得した変更を共有して配信する。RabbitMQにはGraphQL変更の通知経路がないため、既存の取り込みジョブqueueは使用していない。

共有pollerは変更を検出しない間のDB確認間隔を1秒から最大5秒まで段階的に広げ、変更を検出すると1秒に戻す。これにより購読がアイドル状態のときの空検索を減らす一方、アイドル状態から変更を検出するまで最大5秒かかる。改善した点は接続数に比例していた所属確認とイベント検索、およびアイドル中のDB polling負荷である。各Subscriptionは30秒間隔で権限を再確認する。DB queryに失敗した場合は最大30秒まで間隔を広げて再試行し、連続した失敗は復旧時まで一度だけ記録する。PostgreSQL通知などDB pollingをなくす起床手段は未導入のため、この項目は部分解決として残す。
