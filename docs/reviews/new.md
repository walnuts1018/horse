# Horseの追加レビュー

## SubscriptionのDB polling

購入イベントと共有下書きはHousehold単位の共有pollerで検索し、購読数に比例するDB queryを避けている。PostgreSQLのquery tracerを使ったfocused integration testでは、異なるHouseholdの50購読を購入イベント検索1回に、異なるdraftの50購読をdraft検索1回にまとめた。ローカルの試験用PostgreSQLでは、1回の検索にかかった時間はそれぞれ約1.7ms、約1.0msだった。

RabbitMQにはGraphQL変更の配信経路がない。PostgreSQLのLISTEN登録にはpgxでSQL commandを実行する必要があり、Bob DSL以外の生SQLを禁止する規約に沿って導入できない。共有pollerはDB query error時に再試行し、idle中は確認間隔を最大5秒まで広げるが、DB polling自体は残る。実運用の接続数・データ量での負荷と、DB通知を使わずにこの方式を継続できるかの検証が未完了のため、項目は未解決として残す。
