# Horse UI/UXレビュー

## デザイン方針

- 既存の落ち着いた緑系の配色と`Noto Sans JP`を基調にし、実用性と読みやすさを優先する。
- 支払い元と最終負担の違いを明確にし、資金の流れを示す小さな図、揃えた金額、意味の一貫した状態色で理解を助ける。金額と色だけに意味を持たせず、ラベルや状態名も併用する。
- カード、境界線、アイコン、影、動きは情報のグループ、操作対象、状態を伝える場合に使う。意味のないカードの多用や装飾目的のグラデーション、影、アニメーションを避ける。
- 日本語の表示文は対象と操作を具体的に示し、機能説明を重ねるAI調のコピーを避ける。

## 未解決レビュー項目

### 共有下書きの通信断中の編集保持

共有下書きはサーバー同期、複数人の編集、競合表示に対応しています。確定した購入の送信待ちはIndexedDBのoutboxに保存され、共有下書きIDを冪等キーとして送信されます。

共有下書きの編集中は`web/src/pages/purchase-create/model/use-purchase-draft.ts`が共有モードでIndexedDBの読み書きを行いません。`web/src/pages/purchase-create/ui/shared-purchase-draft-page.tsx`の編集内容はサーバー同期が成功するまで画面状態だけにあり、購入を送信待ちにする前の編集内容を通信断中に復元するローカル保存がありません。共有下書きの編集も通信復旧後に再開できる保存方法が必要です。
