# Subscriptionの未検証項目

購入イベントのsnapshot hydrateは複数Householdを一括取得し、Testcontainersの統合テストでquery数がHousehold数に応じて増えないことを検証する。空pollと失敗時の待機間隔は最大5秒まで延長する。

Householdごとのstream cursorは独立しており、異なるHousehold間でcursor値を並べても時系列順にはならない。イベント検索はcursor条件を16,000 Household単位のOR queryに分割し、各chunkから最大100件を取得した後、cursor値で並べ替えて全体を100件に切り詰める。そのため取得優先度はHouseholdごとのcursor値に依存し、cursor差が大きい場合にイベント配信が遅れる可能性がある。pollごとに取得済みイベントのcursorは進むため、有限のbacklogだけから恒久的starvationが起きるとは判断できない。16,000 Household超過時の配信遅延とHousehold数が多い場合のOR query実行計画・負荷は未測定であり、実利用規模で確認する。

本番データ量でのquery実行計画と同時購読時のDB接続競合も未測定であり、実利用の規模に応じて確認する。
