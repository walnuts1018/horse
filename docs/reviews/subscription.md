# Subscriptionの未検証項目

購読pollerはHouseholdとdraftごとにcursorをまとめ、16,000件単位でDB検索を分割する。購入イベントはpollごとに最大100件取得し、itemとpurchaseのsnapshot hydrateをまとめて取得する。空pollと失敗時の待機間隔は最大5秒まで延長する。Postgres adapterの統合テストはitemを持たないdraft購入snapshotを2件と8件で取得し、どちらも8 query以下で、件数によるquery数の増加がないことをassertする。

本番データ量でのquery実行計画、同時購読時のDB接続競合、1回のpollで複数Householdにまたがる購入イベントが多い場合の負荷は未測定である。これらは実利用の規模に応じて確認する。
